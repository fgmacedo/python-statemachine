# UML state machine cases based on PSSM

The cases in `cases/` are generated by `convert.py` from the test suite of the OMG
Precise Semantics of UML State Machines (PSSM) 1.0 specification:

- Source: <https://www.omg.org/spec/PSSM/20181101/PSSM_TestSuite.xmi>
- OMG document number: ptc/18-11-06
- sha256: `c355b249c356774377a46b60345019d827af1ce417bde88e533aa5f39206ae07`

The PSSM specification and its test suite are copyright © Object Management Group, Inc.
and the organizations named in the specification's copyright notice. UML and OMG are
trademarks of the Object Management Group, used here only to name the source.

The repository holds the converter, the harness and the generated cases, never the XMI
itself: the specification's license does not allow posting copies of it on a network
computer, so the XMI is downloaded when needed and never committed, stored or cached. The
cases are *based on* PSSM; passing them is not a conformance claim.

## Layout

- `convert.py`: XMI to native YAML, standard library XML parser, deterministic output.
- `cases/<Category>/<id>.yaml`: one generated case per PSSM test. Do not edit.
- `overlays/<id>.yaml`: hand-written patches the converter applies, for behaviors with logic
  (counters, signals sent from inside the machine) and for CallEvent tests. `cases/` is
  always exactly the converter output for the XMI plus these overlays. In the generated
  statechart, an overlay's native actions run before its trace callback.
- `conftest.py`: the expected failures, per engine, with a reason code, and `LOWERED`: the
  cases that pass only because the converter lowers a construct the library cannot spell
  yet (for example, a junction flattened into guarded transitions). Those passes do not
  show native support for the construct. Every case with a non-empty `requires` is in one
  of the two.
- `test_pssm_cases.py`: runs every case on the sync and the async engine.
- `test_pssm_drift.py`: regenerates the cases and compares them with `cases/`.

## Case format

Each case is a YAML mapping:

- `requires`: UML constructs the case uses that the native format cannot spell yet
  (`choice`, `junction`, `join`, `fork`, `terminate`, `entry_point`, `exit_point`,
  `defer`, `call_event`, `redefinition`, `do_activity_accept`). The statechart is the
  closest loadable approximation.
- `expected_traces`: the accepted traces, taken from the suite's executable oracle.
- `stimulus`: what the tester does, in order, starting with `Start`: `{event, kwargs}`
  sends a signal, `{call, kwargs}` calls an operation, `{trace}` is a token the tester
  traces itself, `trace_result` formats the value a call returned.
- `behaviors`: the trace tokens each callback appends; `{name}` placeholders are filled
  with the event data. `on_invoke_<state>` entries are doActivities; in them,
  `{send: {event}}` sends an event to the machine and `{accept}` parks the doActivity until
  its state is left.
- `statechart`: a native document, loaded untrusted with `statemachine.io.load`.

The converter lowers UML completion transitions to what the library has today: from a
composite state to `done.state.<id>`, from a state with a doActivity to
`done.invoke.<id>`, from a simple state to an eventless transition.

## Running

```bash
timeout 120 uv run pytest tests/uml/pssm -n 4
```

## Regenerating

Download the XMI to a git-ignored location (any directory outside the repository, or the
repository root, where `PSSM_TestSuite.xmi` is ignored), then:

```bash
export PSSM_XMI=/path/to/PSSM_TestSuite.xmi
uv run python -m tests.uml.pssm.convert --out tests/uml/pssm/cases
uv run pytest tests/uml/pssm/test_pssm_drift.py
```

The converter checks the sha256 above before reading the file. Without `PSSM_XMI` the
drift test is skipped; `PSSM_REQUIRED=1` turns the skip into a failure, which is how the
`pssm-drift` CI job runs it.
